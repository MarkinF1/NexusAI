# NexusAI

Веб-интерфейс к подпискам Claude Code и Codex на своём сервере. Это младший брат
Telegram-бота [NexusAITg](https://github.com/MarkinF1/NexusAITg): те же CLI, та же песочница,
только вместо чатов Telegram — сайт с пользователями.

- **Пользователи.** У каждого свой логин и пароль, свои беседы, файлы и общая память
  `MEMORY.md`. Так можно, например, разделить работу и личное. Модель видит только папку своего
  пользователя: это обеспечивает песочница CLI, а не просьба в промпте.
- **Беседы.** Движок (Claude или Codex) выбирается при создании беседы. Модель и уровень
  размышления меняются в шапке.
- **Ответ** приходит потоком: текст и вызовы инструментов видно сразу. Кнопка «Стоп» убивает
  процесс CLI. Ответ продолжается, даже если закрыть вкладку.
- **Файлы.** Прикрепить можно кнопкой 📎 или вставкой картинки из буфера. Файлы, которые модель
  сохранила в `files/for_user`, появляются ссылками под ответом. Все файлы беседы — в 📁.
- **Подписка общая:** вход в `claude` и `codex` выполнен один раз на хосте (`~/.claude`,
  `~/.codex`).

## Установка

Нужны залогиненные `claude` и `codex`, а также `bubblewrap` и `socat` для песочницы claude:

```bash
sudo apt install bubblewrap socat
cd ~/projects/NexusAI
./start.sh          # venv, зависимости, первый админ, systemd-сервис nexus-web
```

После установки сайт открывается на `http://127.0.0.1:8080`. Настройки лежат в `.env`
(см. `.env.example`).

Разовый запуск без systemd: `.venv/bin/python app.py`.

## Пользователи

Администратор управляет пользователями на сайте: «Пользователи» в левом нижнем углу. Карточка
пользователя состоит из четырёх разделов:

- **Информация:** беседы, сообщения, последняя активность, расход подписки и токены. Здесь же
  смена пароля и удаление.
- **Память:** сколько места занято сессиями и файлами, а также лимит в МБ. Если лимит превышен,
  новые файлы не загружаются, а пользователь видит предупреждение. Писать сообщения он
  по-прежнему может.
- **Доступ:** что модели можно делать в песочнице.
  - *Запуск команд* — Bash. У Codex команды есть всегда, но тоже в песочнице.
  - *Изменение файлов* — без этой галочки нельзя трогать `files/` и память. Корень рабочей
    папки остаётся доступным для черновиков: без этого не стартует песочница.
  - *Интернет для команд* — доступ в сеть для curl, pip и git.
  - *Веб-поиск и сайты* — WebFetch/WebSearch и `web_search` у Codex. Сеть для команд они не
    открывают.
  - *Файлы других бесед* — без этой галочки модель видит только текущую беседу и общую память.
- **Сети:** какие нейросети, модели и уровни размышления доступны. Здесь же лимиты на
  5-часовое и недельное окно подписки.
  - Лимит — доля **общего** окна на каждого пользователя: двое по 50% вместе могут потратить
    всё. 100% значит «без лимита».
  - Расход считается как сдвиг общих процентов подписки за время запросов пользователя.
    Точность около 1%.
  - Использование подписки мимо сайта (бот, свой CLI) во время запроса тоже попадёт в расход.
  - Если лимит кончится посреди ответа Claude, ответ остановится. Codex отдаёт проценты только
    после ответа, поэтому для него проверка идёт перед следующим запросом.

Те же операции из консоли:

```bash
.venv/bin/python users.py add work            # обычный пользователь
.venv/bin/python users.py add mark --admin
.venv/bin/python users.py passwd work
.venv/bin/python users.py list
```

## Данные

```
data/nexus.db                     пользователи, их права и входы
data/limits.json                  последний общий снимок процентов подписки
data/users/<id>/usage.json        расход пользователя по окнам и токены
data/users/<id>/claude/           CLAUDE_CONFIG_DIR пользователя (токен — симлинк на хост)
data/users/<id>/codex-home/       CODEX_HOME пользователя (auth.json — симлинк на хост)
data/users/<id>/chats/<chat>.json настройки беседы; .jsonl рядом — её история
data/users/<id>/data/             единственное, что видит модель: MEMORY.md и workspaces/<chat>/
```

## Доступ снаружи

Сайт слушает `NEXUS_HOST:NEXUS_PORT` и умеет работать за обратным прокси (`X-Forwarded-*` от
`NEXUS_TRUSTED_PROXY`). Внешний доступ пока не настроен. Варианты на будущее:

- **Keenetic, KeenDNS → «Веб-приложения»:**
  - в `.env` поставить `NEXUS_HOST=0.0.0.0` и `NEXUS_TRUSTED_PROXY=<IP роутера>`;
  - на роутере опубликовать `http://<IP сервера>:8080` на поддомене. HTTPS роутер выпустит сам.
- **VPN** (WireGuard на Keenetic или Tailscale): наружу ничего не открыто.
- **VPS:** тот же `start.sh` и Caddy перед сайтом.

Это доступ к модели с Bash на твоём сервере, поэтому пароли нужны длинные.

## Тесты

```bash
.venv/bin/python -m unittest test_core
```

Тесты обходятся без сети: настоящий claude подменяется фальшивым скриптом.
